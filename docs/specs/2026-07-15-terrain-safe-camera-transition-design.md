# 3D 地形安全镜头过渡设计

日期：2026-07-15  
状态：已口头批准，待书面复核

## 背景

飞行动画约 2:58～3:15 的高山路段在缩放转场时，镜头会穿入地形。

当前适配器把二维 `cameraForBounds` 计算出的目标中心与 zoom 交给 `easeTo`。`easeTo` 会线性同时插值中心点和 zoom；在 AWS Terrarium 3D 地形（夸张系数 1.4）中，相机可能尚未充分拉高便横向穿越山脊，造成钻入地面的视觉错误。

MapLibre 5.24 的相机 API 提供 `freezeElevation`，用于 3D 地图动画期间维持基于海平面的稳定相机高度，并在动画结束后重新按目标地形校正。

## 决策

将有动画时长的包围盒场景切换从：

```js
map.easeTo({ ...target, duration, essential: true })
```

改为地形安全的飞行轨迹：

```js
map.flyTo({
  ...target,
  duration,
  essential: true,
  freezeElevation: true,
})
```

`flyTo` 使用先拉远/升高、再平移、最后接近目标的路径，避免线性 zoom 在高山中横穿地形；`freezeElevation` 防止飞行期间因新地形瓦片加载或目标海拔变化而改变相机高度。

## 保持不变

- 镜头转场时长仍由时间轴传入，最长约 3 秒。
- 总览俯角保持 25°。
- 地形夸张系数保持 1.4。
- 路线、小车运动、已走路线着色、圆形揭幕和旁白时序均不变。
- 首次定位、拖动进度条、容器 resize 仍使用 `jumpTo`，避免出现延迟追赶。

## 中断与连续性

- 新场景到来时，MapLibre 自动中断前一个 `flyTo` 并从当前相机状态过渡到新目标。
- 场景内继续按 `sceneId` 记忆化，不会每帧重启动画。
- 动画结束后由 MapLibre 重新结合目标地形计算中心/zoom，避免永久偏离目标包围盒。

## 测试与验收

### 自动验证

- 抽出纯函数构造相机转场选项，测试：
  - 动画场景选择 `flyTo`。
  - `freezeElevation === true`。
  - 时长、中心、zoom、pitch、bearing 和 padding 原样保留。
  - 无动画场景仍选择 `jumpTo`。
- 全量单测与生产构建通过。

### 浏览器手测

- 重点回放 2:58～3:15。
- 转场应先拉远/升高，再横移，最后平滑落到下一段总览。
- 任何一帧都不应出现地形从镜头前方切开、镜头钻进山体或画面被地表完全遮挡。
- 转场总时长体感仍约 3 秒，小车节奏不变。

## 不在本次范围

- 动态调整地形夸张系数。
- 临时关闭 3D 地形。
- 修改地图与展示页的整体时长占比。
