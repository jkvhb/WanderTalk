# 固定 318 重规划与底层校验设计

日期：2026-07-18  
状态：待用户书面复核

## 1. 目标

依据用户提供的《318 川藏线路书》重建固定 318 旗舰作品的九天主路线，并从数据入口和播放入口同时阻止重复地点、重复讲解与零距离飞行段。

本阶段同时为 PRD v3 的通用规划代理预留地点身份和节点角色边界，但不建设完整对话代理、联网事实核验队列或通用发布系统。

## 2. 路线范围

主作品保持九天。拉萨市内及周边内容作为主线结束后的附加篇，不进入 318 主线时间轴。

### 第 1 天：成都—康定

主路线：成都 → 雅安 → 天全 → 二郎山 → 泸定 → 康定。  
重点讲解：成都、雅安、泸定、康定。  
住宿：康定。

### 第 2 天：康定—雅江

主路线：康定 → 折多山垭口 → 新都桥 → 雅江。  
重点讲解：折多山、新都桥、雅江。  
住宿：雅江。  
雅哈垭口、冷嘎措、塔公草原、墨石公园和雅拉雪山只记录为可选支线，不加入主线动画。

### 第 3 天：雅江—巴塘

主路线：雅江 → 天路十八弯 → 剪子弯山 → 卡子拉山 → 理塘 → 毛垭大草原 → 海子山姊妹湖 → 巴塘。  
重点讲解：天路十八弯、剪子弯山／卡子拉山、理塘、毛垭大草原、姊妹湖、巴塘。  
住宿：巴塘。  
稻城亚丁和色达只记录为可选支线。

### 第 4 天：巴塘—左贡

主路线：巴塘 → 金沙江大桥 → 宗巴拉山 → 芒康 → 拉乌山 → 如美 → 觉巴山 → 东达山 → 左贡。  
重点讲解：金沙江大桥、芒康、如美／觉巴山、东达山、左贡。  
住宿：左贡。

### 第 5 天：左贡—八宿

主路线：左贡 → 邦达 → 业拉山 → 怒江七十二拐 → 怒江大桥 → 八宿。  
重点讲解：邦达草原与业拉山、怒江七十二拐、怒江大桥、八宿。  
住宿：八宿。

### 第 6 天：八宿—波密

主路线：八宿 → 安久拉山 → 然乌湖 → 米堆冰川 → 波密。  
重点讲解：安久拉山、然乌湖、米堆冰川、波密。  
住宿：波密。  
来古冰川作为可选支线，不与米堆冰川同时强制加入当天主线。

### 第 7 天：波密—索松村

主路线：波密 → 古乡湖 → 通麦 → 鲁朗 → 色季拉山 → 索松村。  
重点讲解：通麦、鲁朗、色季拉山、索松村与南迦巴瓦峰。  
住宿：索松村。

### 第 8 天：索松村—工布江达

主路线：索松村 → 林芝 → 巴松措 → 工布江达。  
重点讲解：林芝、巴松措、工布江达。  
住宿：工布江达。

### 第 9 天：工布江达—拉萨

主路线：工布江达 → 米拉山垭口 → 墨竹工卡 → 拉萨。  
重点讲解：米拉山、墨竹工卡、拉萨。  
终点：拉萨。  
思金拉措和直贡梯寺作为可选支线。

### 拉萨附加篇

包含布达拉宫，以及羊卓雍措／纳木错二选一。附加篇不计入九天 318 主线，不参与主线里程、章节编号或飞行动画连续性校验。

## 3. 兼容式数据升级

现有播放器继续消费 `days[].waypoints[]`，不在本阶段整体更换数据结构。每个 waypoint 新增或明确以下字段：

- `placeId`：真实地点的稳定身份；同一地点跨日复用同一 ID；
- `narrate`：是否进入讲解节点集合；默认根据旁白存在性兼容旧数据；
- `roles`：可同时包含 `origin`、`route`、`stop`、`overnight`，避免住宿地或起终点只能表达一种职责；
- `routeType`：`main` 或 `optional`；可选支线不进入主线 waypoint 序列；
- `source`：固定作品记录来源文档页码或人工核验标记，后续可扩展 URL 和抓取时间。`day` 同时增加 `overnightPlaceId`，住宿校验以地点身份为准而不是只比较名称。

固定预设中新加入的地点必须通过现有地点检索／路线工具解析坐标，并在地图中人工抽查；模型不得凭记忆生成坐标、距离或海拔。`placeId` 在固定作品中人工确定，后续再迁移到通用地点服务。

每天为了路线计算仍可重复保存上一日终点作为当天起点，但必须满足：

1. 两个引用使用相同 `placeId`；
2. 坐标在容差范围内一致；
3. 下一日的起点 `narrate=false`；
4. 不为该边界创建飞行段或第二次讲解。

## 4. 规划校验器

新增纯函数规划校验器，返回结构化问题，不直接依赖 Vue、地图或网络。每个问题包含 `code`、`severity`、`dayNumber`、`waypointIndex` 和可读信息。

首批规则：

- `INVALID_COORDINATE`：坐标缺失或超出合法范围；
- `DUPLICATE_DAY_NUMBER`：天数编号重复或不连续；
- `EMPTY_DAY`：当天没有可计算路线；
- `DUPLICATE_PLACE`：同一天或相邻讲解中重复同一地点；
- `DUPLICATE_NARRATION`：同一 `placeId` 在连续节点被讲解两次；
- `ZERO_DISTANCE_LEG`：非跨日连续引用产生零距离路线段；
- `DAY_BOUNDARY_MISMATCH`：前一天终点与下一天起点无法连续衔接；
- `OPTIONAL_IN_MAIN_ROUTE`：可选支线误入主路线；
- `OVERNIGHT_MISMATCH`：住宿地与当天终点不一致。

地点相同性按以下顺序判断：

1. `placeId` 相同；
2. 规范化名称相同且坐标距离小于 1 公里；
3. 坐标距离小于 50 米时视为同一物理地点并给出名称冲突提示。

校验器只报告问题。固定预设必须在提交前达到零 error；warning 需要在设计或数据注释中说明。未来 AI 规划流程可以把问题列表交给模型局部修复。

## 5. 播放层兜底

`collectNarratedStops` 在收集讲解节点时执行最后一道防线：

- 相邻节点属于同一地点时只保留一个讲解节点；
- 跨日重复起点不生成零长度 `routeToHere`；
- 被跳过节点之后的真实路线仍正确拼接到下一讲解点；
- 没有有效长度的路线不创建小车飞行场景；
- 去重不得按名称全局删除，避免不同城市中合法的同名地点被误合并。

播放层兜底不替代数据校验。开发界面仍应展示规划问题，固定作品不得依赖兜底后带病发布。

## 6. 资料规范化

导入参考路书时先形成候选地点清单，再进入固定预设。已确认的原文异常包括：

- “米堆冰川”连续出现两次，只保留一次；
- 文档后段存在两个“第八天”，按九天主线重新编号；
- 来古冰川、稻城亚丁、色达、塔公／墨石等内容标记为可选支线；
- 未提供距离或耗时的节点不直接将空值当成已核验事实；
- 餐饮、住宿、票价和开放状态属于动态信息，本阶段只作为参考资料，不写入无法持续核验的固定事实旁白。

## 7. 实施边界

本阶段包含：

- 更新固定 318 九天预设路线与重点讲解节点；
- 为预设节点增加地点身份和角色字段；
- 新增纯函数规划校验器及测试；
- 修复讲解节点收集与零距离飞行兜底；
- 增加固定预设合法性回归测试；
- 保持现有编辑器、路线计算、配音、搜图、动效和播放器兼容。

本阶段不包含：

- 通用对话式规划代理；
- 自动联网核验住宿、餐饮、门票和实时路况；
- 用户上传任意 PDF 后自动解析为路线；
- 完整地点主数据服务；
- 模型微调；
- 拉萨附加篇的正式视觉制作。

## 8. 测试与验收

### 自动测试

- 九天编号连续，住宿顺序为康定、雅江、巴塘、左贡、八宿、波密、索松村、工布江达、拉萨；
- 每天终点与下一天起点共享 `placeId`，且下一日起点不重复讲解；
- 理塘、米堆冰川等地点在讲解时间轴中只出现一次；
- 主路线不包含标记为 optional 的节点；
- 固定预设通过规划校验器且无 error；
- 人工构造的重复节点、零距离路段、错误天数和跨日断裂都能被检测；
- 播放兜底能合并跨日重复节点并保持后续路线；
- 全量测试与生产构建通过。

### 浏览器手测

- 逐日检查地图路线与《318 川藏线路书》主线一致；
- 第 3 天理塘只出现一次讲解和一次展示页；
- 第 6 天米堆冰川只出现一次；
- 每日章节从上一日住宿地自然继续，不出现原地小车、异常 bounds 或穿地镜头；
- 可选支线不会被主线动画误播放；
- 九天结束于拉萨，附加篇不改变主线进度。
