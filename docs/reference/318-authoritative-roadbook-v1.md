## 1. 这份底稿是什么

这不是面向游客的最终攻略，而是 WanderTalk 内部生成完整作品时共同遵守的“事实与边界清单”。路线 AI、文案 AI、图片搜索、语音合成和动画播放器都必须以本底稿为上游约束。

本底稿解决四个问题：

1. 主线节点一个不少，AI 不得按自己的偏好删减；
2. 路线节点、讲解节点、住宿节点和可选支线分开表达；
3. 同一地点跨日只讲解一次，避免重复文案、重复配图和零距离动画；
4. 坐标、道路、海拔和荣誉称号必须由工具或可靠来源核验，模型不得凭记忆填写。

餐厅、酒店、预算、票价和实时开放状态暂不录入。它们属于会频繁变化的动态信息，后续应由单独工具按出行日期查询。

## 2. 资料优先级

发生冲突时，按以下顺序处理：

1. 用户明确确认的路线选择；
2. 地图地点检索与实际驾车路线返回结果；
3. 项目地点核验表；
4. 用户提供的 PDF 路书；
5. AI 生成内容。

AI 只能整理、改写和组织内容，不能覆盖上级资料。未核验的信息必须标记为“待核验”，不能包装成确定事实。

## 3. 节点等级与生成规则

### A 级：核心讲解点

- 建议播报 35～50 秒；
- 需要完整的地理背景、故事或文化价值和情绪推进；
- 原则上配置 3～5 张经过地点身份核验的图片；
- 在章节中承担记忆点或情绪高潮。

### B 级：标准讲解点

- 建议播报 18～30 秒；
- 集中解释一个最有辨识度的事实或景观；
- 原则上配置 2～3 张图片；
- 不与相邻节点重复使用同一种描述。

### C 级：沿途提示点

- 建议播报 8～15 秒；
- 用于服务区、道路分界、路口和短暂停留点；
- 可以只配置 1～2 张图片或使用地图信息卡；
- 不强行拔高为核心景点。

### 跨日节点

每天起点引用前一天终点的同一个 `placeId`。它参与当天路线计算，但不再次生成旁白、图片、语音或展示动画。章节开场可以用一句话提示“从某地出发”。

## 15. 文案生成约束

### 必须做到

- 所有主线节点均生成内容，不能因图片少、资料少或模型偏好而跳过；
- 相邻垭口、草原和县城必须使用不同叙事角度；
- 每个节点至少包含一个可验证的核心事实和一个可感知的现场细节；
- 核心节点可使用历史、人物、工程、地理和文化故事提升感染力，但每个具体称号和数据都要有来源；
- 文案需要形成逐日情绪曲线，而不是 46 段互不相干的景点百科；
- 风险提示保持克制、实用，不渲染恐惧；
- 住宿地在前一天到达时完成讲解，次日只作出发提示。

### 禁止事项

- 不得杜撰“中国十大”“世界之最”“国家地理评选”等荣誉；
- 不得把县域支线景点描述成主线路边可见；
- 不得将旧路、老垭口描述成始终可通行；
- 不得为了配合错误图片反向修改地点事实；
- 不得重复讲解理塘、米堆冰川及跨日住宿地；
- 不得把八宿错误描述为“G318 第一高垭口”。

## 16. 图片自动匹配约束

每张图片必须同时通过“地点身份”和“视觉内容”两层检查。

### 地点身份

- 标题、标签、简介、来源页面或摄影说明中至少有一项明确指向节点；
- 同名地点必须结合省、市、县或附近地标消歧；
- 桥梁、垭口、冰川和湖泊采用严格模式，不能只按大类相似度匹配。

### 视觉内容

- 图片需要覆盖本节点文案实际讲到的内容；
- 搜不到对应图片时，先调整关键词、改用英文名/行政区/邻近地标或更换图片源；
- 仍然搜不到时标记“素材不足”，不能拿其他地点图片补位；
- PDF 中的图片可用于人工判断应有的视觉特征，暂时不用关注版权问题。

- 金沙江大桥必须检索“竹巴笼金沙江大桥、G318、巴塘、芒康”，排除伦敦桥和城市跨江桥；
